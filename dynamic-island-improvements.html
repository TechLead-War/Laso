Laso · Dynamic Island Review

What we could have done better

A ranked, impact-per-effort board of improvements for the Laso Live Activities, synthesized across design, content, engineering, accessibility, and analytics. The theme is restraint: a surface glanced at for seconds cannot carry seven competing elements. Most of the top wins are deletion, not addition. Items already shipped this release are dropped; their accessibility and lifecycle follow-ons are kept.

Recommendations board

ranked by impact-per-effort · ★ = do next
Do next (top 3) — quick high-impact wins
1Cut the expanded island to one hero + one insight + one action

The expanded and lock cards pack 6–7 competing elements. A two-second glance can't carry that — it defeats glanceability and premium restraint. Drop the 3-stat row and day-progress strip; keep ring + one insight + the action. Mostly deletion.

Lowuber.com/blog/live-activity-on-ios
2Log the compact-pill / Lock Screen deep-link tap

The core success signal — did the glance drive a tap into the app — is invisible for all three activities. One event in handleDeepLink before navigate(to:) makes tap-through rate computable. Add ?src= to separate the surfaces. Already identified, still unfixed.

Lowdeveloper.apple.com · launch from LA
3Fold staleness into the VoiceOver score label

A sighted user sees the greyed ring; a VoiceOver user is told a stale score with full confidence. When stale, append the age phrase: "Recovery 75 out of 100, updated 22 hours ago." A real trust and correctness fix, not polish.

Lowdeveloper.apple.com · accessible LA
More low-effort wins
4Set distinct relevanceScores instead of force-ending the loser

All managers omit relevanceScore (defaults to 0.0 = undefined ordering). The code tears down the loser, killing its score and still leaving a race window. relevanceScore is Apple's intended mechanism: live 100, wind-down 75, score 25, night near-0. Lets both coexist with correct priority.

Lowdeveloper.apple.com · relevanceScore
5Make the compact pill non-redundant

Compact leading is a full ring and trailing is a 3-digit number — they say the same thing twice and widen the pill against "snug to the sensor." Show the ring alone with a tiny mode glyph, or cap the number. Compact is the most-seen state.

LowWWDC23 · 10194
6Add a Large Content Viewer to the small numbers

With fonts now pinned, low-vision users get zero scaling on the score, orb number, HRV and steps. .accessibilityShowsLargeContentViewer is Apple's documented compensation: long-press shows the value large without changing the at-rest layout. Closes the hole pinning created.

Lowcreatewithswift.com · large text
7Remove the affordance ambiguity between button and chip

A tappable Button capsule sits beside a near-identical non-tappable chip in the same row — the chip looks pressable. Restyle the chip as plain text, or move it to the lock card only, so the one real action is unmistakable.

LowHIG · Live Activities
8Drive grey-out from system isStale, not a 20h clock

Freshness uses two thresholds that can contradict — render heuristic lastUpdated > 20h vs system staleDate = midnight. The ring can look confident while the system already considers it stale. Drive "old data" UI from isStale and advance staleDate on each update — one source of truth.

Lowdeveloper.apple.com · isStale
9Attribute Live Activity opens in session source

A LA tap mints a session counted as .organic / opened_from='app_icon' because nothing sets pendingSessionSource. The taxonomy comment even promises "live_activity" values the enum never produces. Set the source in handleDeepLink; implement or delete the promised cases.

Lowcode · SessionTracker / AppAnalytics
10Measure time-to-tap (dwell proxy)

No dwell API exists, but CoachActionBridge already stamps a pending timestamp — log now − pendingTimestamp on the action event, and stamp activity-start time in the App Group for the deep-link path. Proxies engagement quality and helps tune staleDate windows. Cheap, timestamp already exists.

Lowcode · CoachActionIntents / ContentView
11Don't hold a Live Activity overnight with nothing to act on

Night mode renders a full card with a passive readout and a .noop action — an always-on health readout, which Apple explicitly calls the job of a widget/complication. At night drop relevanceScore near-0 or end the activity and let a widget carry the number.

Lowdeveloper.apple.com/news · LA dos & don'ts
12Fire one AlertConfiguration at the key moment

No manager uses AlertConfiguration, so WindDown silently re-renders when the bedtime window opens or HRV flips low — the user may never glance. One alert on that single transition lights up the island and a synced Watch. Use once per night to serve bedtime behavior change without nagging.

LowWWDC23 · 10184
13Let completion cards linger instead of vanishing

TodayScore and WindDown end with .immediate, so "Session complete" / "You hit your bedtime" disappear with no final state. Use .default or a short .after(date) for genuine end states so the completion moment gets a beat of visibility, reinforcing the habit loop.

LowWWDC23 · 10184
14Cut redundant progress chrome

The lock card stacks three time encodings (strip + day-track ring + score orb); WindDown shows moon-arc + countdown + stage phrase, all describing "time to bed." Decorative motion, not information. Keep one time signal per surface — for WindDown keep the numeric countdown, drop the phrase.

LowHIG · Live Activities
15Standardize WindDown's background surface

WindDown uses a 0.82-opacity overlay that can let wallpaper bleed through and reduce contrast; the other two use the opaque surfaceBase. A consistency and contrast nit, but a cheap one.

LowHIG · Live Activities
Medium effort
16Stop pushing an update on every breathwork phase

Breathwork pushes a full activity.update() per phase — ~50–100 updates over 4–5 min — yet the widget already derives phase from sessionStartDate and self-advances via Text(timerInterval:). The pushes are redundant, drain the budget, and can stutter the island. Keep update() only for pause/resume/protocol change.

MedWWDC23 · 10185
17Make the hero number match the mode (or delete heroValue)

heroValue (readiness/strain/tonight) is computed and stored but the ring always renders overallScore, while the eyebrow says "Strain" or "Readiness." The most prominent element contradicts its own caption, and heroValue is dead state. Render it per mode, or delete it.

Medvertu.com · whoop vs oura
18Re-derive mode by the clock, not the last refresh

deriveCoachContext runs once at update time with CoachMode.current, so a 09:00 refresh still says "Readiness / Set intention" at 14:00. Schedule mode-boundary updates (10/18/22h) or render mode from the current clock in the widget. Otherwise the time-of-day relevance breaks for most of the day.

Meddeveloper.apple.com · staleDate
19Guarantee overnight teardown with a dismissal deadline

TodayScore relies on an in-process midnight Task plus staleDate=midnight. staleDate only dims, it doesn't end — if the app is suspended before midnight, yesterday's score sits live until next launch. End with dismissalPolicy: .after(nextMidnight) at start so iOS removes it even if the process never wakes.

Meddeveloper.apple.com · staleDate
20Cap Dynamic Type with a range instead of fully pinning

Pinning fixed clipping but means zero scaling for large-text users. Apple's sanctioned middle path is adaptive styles with a capped range — e.g. .dynamicTypeSize(.large ... .accessibility1) on the lock card, tighter on the island — so text grows partway then stops within the cap. Pair with #6.

Medyaacoub.github.io · dynamic type
21Lift WindDown's dismissal-reason observer into all three

Only WindDown observes activityStateUpdates to log user_swiped vs system_ended. TodayScore and Breathwork have no observer, so a swipe-away is never recorded — you can't tell a valued completion from an irritated swipe for two of three surfaces. Share the WWDC loop.

MedWWDC23 · 10184
22Wrap content around the sensor, not a sparse "forehead"

All three widgets leave the expanded centre empty and dump every wide element into .bottom, producing the "forehead" shape WWDC warns against. Move a lightweight head signal (mode label or score) up to flank the camera so the layout hugs the sensor and the bottom holds only hero + action.

MedWWDC23 · 10194
23Enrich start_failed with a reason

All three log start_failed with no detail, so you can't tell areActivitiesEnabled==false from the 8-activity cap or a payload error. Attach the error type and the enabled flag, plus a one-time live_activities_enabled user property — turns a flat count into a funnel and sizes the audience.

Meddeveloper.apple.com · ActivityKit
24Add a per-instance activity id to join start → tap → dismissal

Events carry activity_kind but no shared instance id, so you can only compute ratio-of-aggregates, not true per-impression conversion. Generate an activity_instance_id at start and echo it on the start event, the widgetURL query, and the action intent.

Medonesignal.com · live activities
25Centralize coaching copy and band thresholds

Insight strings are hardcoded ternary ladders, despite a comment claiming they're "generated server-side from ML context"; thresholds (30/70 strain, 85/70/50 readiness) are inline magic numbers. Move copy into TodayScoreCopy, pull thresholds into the named clinical config with a source, and either wire the server insight or fix the comment.

Medcreatewithswift.com · glanceable widgets
26Reduce VoiceOver-focusable elements per region

The expanded leading region exposes a bare Image and the trailing stamp is a separate raw Text, so each region is several independent elements. ActivityKit re-reads each region 2–4× after every update (known bug) — fewer focusable nodes is the only mitigation. Keep one concise label per region.

Meddeveloper.apple.com/forums · 719235
Higher effort
27Use ViewThatFits / AnyLayout so the card reflows

The expanded card is one rigid HStack relying on minimumScaleFactor(0.7) — at large type everything just shrinks. ViewThatFits (Apple's exact answer to "widget overflows at large type") with a roomy and a stacked fallback lets text grow within the cap rather than shrink. Restructures the layout; do after the simpler cap (#20).
